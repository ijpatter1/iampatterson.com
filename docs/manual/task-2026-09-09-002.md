## Why this is a card and not a script

`gcloud billing` exposes `accounts`, `budgets` and `projects` — and no export or
sink subcommand. Verified 2026-09-09 against the installed SDK, not assumed. The
BigQuery billing export is configured at the **billing account** level in the
Cloud Console, and there is no public API for the toggle either, so this is a
genuine browser step rather than a scripting gap.

Everything around it is already done. `iampatterson:billing_export` exists in
`US`, matching the location of `iampatterson_raw` and `iampatterson_marts`, so
the Console step is a destination selection rather than a dataset creation.

## Why bother

The only cost signal today is the `metabase-project-budget` alert at $200/month
(thresholds 50/90/100%, notifying `ops-email` since [13.1]). An alert tells you
the total crossed a line. It cannot tell you which service moved, and the two
candidates worth acting on — `sgtm` and `metabase`, both running
`min-instances=1` with `cpu-throttling: false`, so CPU is allocated
continuously — are indistinguishable in it.

**Backfill is not retroactive.** The export starts collecting from the day it is
enabled, so the sooner it is on, the sooner there is a week of data to read.

## Steps

### 1. Open the billing export settings

<https://console.cloud.google.com/billing/01FFAB-2D440A-4D16D8/export/bigquery>

That is the billing account already linked to `iampatterson` (confirmed with
`gcloud billing projects describe iampatterson`). If the link 404s, reach it as
**Billing → (select the account) → Billing export → BigQuery export**.

### 2. Enable the one export that answers the question

Under **Detailed usage cost**, click **Edit settings** and select:

- **Project:** `iampatterson`
- **Dataset:** `billing_export`

Save.

Detailed usage cost is the one to enable: it carries per-SKU, per-resource rows,
which is what attributes a dollar to `sgtm` rather than to Cloud Run in general.
Standard usage cost is coarser and answers a question you can already answer.
Pricing export is a rate card, not spend — skip both unless you want them.

### 3. Confirm it took

```bash
bq ls --project_id=iampatterson billing_export
```

Nothing appears immediately. The first table lands within a few hours to a day,
named `gcp_billing_export_resource_v1_01FFAB_2D440A_4D16D8`. Empty output on the
same day is expected and is not a failure.

## How you know it worked

Once a table exists, this answers the question that prompted the whole exercise —
which service actually costs what, over whatever window has accumulated:

```sql
SELECT
  service.description AS service,
  ROUND(SUM(cost), 2) AS cost,
  ROUND(SUM(SUM(cost)) OVER () , 2) AS total
FROM `iampatterson.billing_export.gcp_billing_export_resource_v1_01FFAB_2D440A_4D16D8`
WHERE DATE(usage_start_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 30 DAY)
GROUP BY service
ORDER BY cost DESC
```

And the narrower one the backlog actually turns on — whether always-allocated CPU
on those two services is worth what it costs:

```sql
SELECT
  resource.name AS resource,
  sku.description AS sku,
  ROUND(SUM(cost), 2) AS cost
FROM `iampatterson.billing_export.gcp_billing_export_resource_v1_01FFAB_2D440A_4D16D8`
WHERE service.description = 'Cloud Run'
  AND DATE(usage_start_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 30 DAY)
GROUP BY resource, sku
ORDER BY cost DESC
```

Metabase already holds a connection to this project, so a dashboard card over
either query is a small follow-on if the numbers turn out to be worth watching.
