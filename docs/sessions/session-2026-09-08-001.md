## What the gate caught that mattered

**A live production bug on the site's centrepiece.** The apex 307-redirects to
`https://www.iampatterson.com`, so `www` is the browser origin for every real
visitor — and it was missing from event-stream's `ALLOWED_ORIGINS`. The service
falls back to `ALLOWED_ORIGINS[0]` for an unlisted origin, so a `www` client
received `Access-Control-Allow-Origin: https://iampatterson-com.vercel.app`, the
browser rejected the mismatch, and `EventSource` failed. **The real-time overlay
— the thesis the whole site exists to demonstrate — did not work in production.**
It worked from the bare apex, which is why it went unnoticed.

Pre-existing, not caused by this branch. But `env` is not in that resource's
`ignore_changes`, so the branch was about to make it durable. Fixed in all three
places the value is declared, with `www` first so the fallback names the real
site. Eight pins, three of which fail against the pre-fix configuration.

**An accidental five-month image upgrade, found while fixing the tool that should
have reported it.** Revision `sgtm-00015-kdj` — the `--max-instances` change on
2026-09-05 — silently carried production sGTM from the 2026-04-03 digest to
current `:stable`. A tag in a Cloud Run service spec is re-resolved by *any*
`gcloud run services update`, so it is not a passive default. That is precisely
the risk 13.2's decision was written to remove, and it happened hours after the
decision was recorded. Both services and `cloud-run.tf` now carry an explicit
digest, so the pin is implemented rather than merely decided.

**A guard written this morning that never fired.** The `verify` atomic-write
guard in `retention/apply.sh` was dead code: a redirected brace group reports its
*last* command, and `set -e` is suppressed inside an `if` condition, so `mv`
always published and the `else` branch was unreachable. The ultra found it. **The
first fix was also wrong** — checking the record for section markers passed a
substantively empty table, because a failing measurement prints nothing while the
awk formatting it still emits its `END` block. The working version makes each
measurement report its own failure, verified three ways: healthy run publishes,
induced mid-table failure refuses, previous record survives.

This is the **second** time this project has been bitten by assuming a shell
construct propagates failure. Phase 12's Critical was `write_diff …; RC=$?`
aborting under errexit. Same family, opposite direction. Worth treating as a
pattern rather than two coincidences: **in bash, verify the failure path with an
induced failure, never by reading the code.**

**Eight false claims in records.** The rehearsal count was wrong in four files (I
claimed 9 rehearsed / 3 reasoned; it is 6 / 5 / 1 partial, and I had named only
the three strongest reasons). A runbook entry asserted an alert had fired that
never fired. The 13.4 record opened by saying changes were not made and kept that
opening after they were. 13.2's decision was recorded as implemented in declared
configuration when it was not.

**Two tests that certified false claims.** The alert→entry test asserted
substring containment plus separate file existence, so a table row with an alert
name and no link passed both — the same vacuous-pin class the boundary review had
just found in 13.5's wording, reproduced in the test written to prevent it. And
the cadence test pinned "first Monday", which `schedule.day` cannot produce under
a monthly interval.

and then repeated the mistake exactly.

That is the only change that prevents this recurring a third time.
