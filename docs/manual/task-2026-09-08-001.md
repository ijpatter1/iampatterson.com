## Context

The Tag Manager API does not authorize on GCP IAM. A caller reaches a container
because it is a **user on the GTM account**, added through the Tag Manager
interface — there is no `gcloud` command, no Terraform resource, and no API
call that grants it. That is why this is a card.

The identity is new and purpose-built: `gtm-reconciler@iampatterson.iam.gserviceaccount.com`,
created 2026-09-08. It replaces the arrangement the retiring scripts used, where
`deploy-phase6.js` and `deploy-claudish.js` read a service-account **key** from
`GOOGLE_APPLICATION_CREDENTIALS`. No key exists for this account and none should
be created: locally it is reached by impersonation, and in CI by Workload
Identity Federation, which is what 14.3 requires ("no service-account key in the
repository").

Ian's own Google account cannot be used instead. `gcloud auth application-default
login --scopes=…tagmanager.readonly` is refused with **"This app is blocked"** —
gcloud's built-in OAuth client is verified for Google Cloud scopes only, and Tag
Manager sits outside that set. The block is a property of the client, not of the
account's permissions.

## Steps

1. Open <https://tagmanager.google.com> and sign in as the owner of account
   `6346433751`.
2. **Admin → Account User Management** (account level, not container level).
3. Add `gtm-reconciler@iampatterson.iam.gserviceaccount.com`.
4. Account permission: **User** is enough. Do not grant Admin.
5. Container permissions, for both `GTM-MWHFMTZN` (web) and `GTM-NTTKZFWD`

   - **Read** — enough for 14.1's census and every dry run.
   - **Publish** — needed later, for the apply and publish steps of 14.1 and for
     14.3's live apply. Grant Read now if you would rather see the census before
     handing over write access; the deliverable is sequenced so the census comes
     first and nothing is written until it is recorded.
6. Save.

## Verification

From the repository root:

```
CLOUDSDK_CORE_PROJECT=iampatterson gcloud auth print-access-token \
  --impersonate-service-account=gtm-reconciler@iampatterson.iam.gserviceaccount.com \
  --scopes=https://www.googleapis.com/auth/tagmanager.readonly
```

That exercises the impersonation path, not the GTM grant. **Confirmed working
2026-09-08**: it mints a 1,024-character token carrying the Tag Manager scope.
The first three attempts returned `IAM_PERMISSION_DENIED` on
`iam.serviceAccounts.getAccessToken` while the freshly created
`roles/iam.serviceAccountTokenCreator` binding propagated; it succeeded a few
minutes later with nothing changed. Treat an early denial as propagation, not as
a broken setup. Note that `gcloud auth print-access-token` accepts no `--project`
flag, so `CLOUDSDK_CORE_PROJECT` is required — the CLI default is
`holdout-500412`.

With a token in hand, this returns the account once membership is granted:

```
curl -s -H "Authorization: Bearer $TOKEN" \
  https://tagmanager.googleapis.com/tagmanager/v2/accounts
```

Measured 2026-09-08, before the grant: **HTTP 200 with zero accounts** — not a
`403`. The identity authenticates fine and simply sees nothing, which is the
signature of a valid caller with no account membership. After step 6 the same
call should list account `6346433751`. An empty list is the "not done yet"
signal; there is no error to wait for.
